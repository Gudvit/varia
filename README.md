# Варя — полная медицинская хронология

Сведённая история болезни кошки Вари: онкология молочной железы, операции,
химиотерапия, лабораторная динамика, офтальмология и кардиология за период
**24.06.2025 – 23.09.2026**.

Отчёт составлен владелицей по фотографиям документов из нескольких клиник
и лабораторий (LoVet, ALVET, Retina, ALPHAVET, IDEXX, ALAB) и предназначен
для передачи новому врачу или консультирующему специалисту.

> Документ не заменяет осмотр и заключение ветеринарного врача.

**Читать онлайн:** <https://gudvit.github.io/varia/>

Документ открывается «Клиническим резюме для врача» — одностраничной сводкой,
по которой новый онколог за 1–2 минуты видит диагноз, четыре операции, обе линии
химиотерапии, активные проблемы и то, что требует решения в первую очередь.
Дальше идёт полная история из 16 разделов.

Вторая страница, **«Анализ»**, — отдельный документ в том же меню.
Он не повторяет хронологию, а разбирает две определяющие сейчас проблемы —
роговицу и дыхание/плевральный выпот: что в накопленных данных сопоставимо,
что менялось одновременно с лечением, какие выводы данные выдерживают.
Каждый разбор заканчивается выводом.

Последнее обновление — 24.09.2026: добавлены документы 21.09–23.09.2026
(онкологический контроль LoVet 21.09, 5-й визит офтальмолога Retina 23.09
с рекомендацией срочной операции, срочный визит LoVet 23.09, рукописный
протокол наркоза); в «Анализ» добавлен раздел о том, какие выводы

## Чтение

Откройте `index.html` в браузере — оглавление с подсветкой текущего раздела,
переключатель между двумя документами в его шапке, светлая и тёмная темы,
печать в PDF через «Печать» (`Cmd/Ctrl + P`). Каждая страница печатается
отдельно.

## Сборка после правок

```bash
npm install   # один раз
npm run build # final_report.md → index.html, analysis.md → analysis.html
```

Пуш в `main` запускает workflow `.github/workflows/pages.yml`: он пересобирает
обе страницы из Markdown-источников и публикует их на GitHub Pages, поэтому
опубликованная версия всегда соответствует источнику.

Перед первой публикацией GitHub Pages должен быть включён в настройках
репозитория: **Settings → Pages → Build and deployment → Source:
GitHub Actions**. Workflow не включает Pages автоматически, потому что
`GITHUB_TOKEN` не имеет прав на создание Pages site.

Сборщик размечает структуру отчёта: нумерованные разделы, годовые срезы
хронологии, датированные записи визитов, врезки ⚠️ с расхождениями между
документами и лабораторные таблицы с закреплённым первым столбцом.
Изменять `index.html` и `analysis.html` вручную не нужно — они перезаписываются
при каждой сборке. Чтобы добавить третью страницу, достаточно дописать её
в список `PAGES` в начале `build.js`.
